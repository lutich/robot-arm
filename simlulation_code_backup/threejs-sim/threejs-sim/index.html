    Manual calibration
    How the matching works
    1. The mat's six ArUco markers have known corners (mm). They are found in the frame (in the browser, or clicked by hand).
    2. A homography maps the mat plane to the image (normalised DLT, at least 4 points).
    3. The homography gives the focal length (its two rotation columns must be orthogonal and of equal length) and a first pose.
    4. Levenberg-Marquardt then minimises the reprojection error over pose, focal length and principal point.
    5. Green outlines: markers found in the frame. Orange: markers reprojected with the fitted camera. Red lines: the error, 5× enlarged.
    Arm tracking AprilTags 106–109 on the wrist and gripper, both cameras combined

    Tags on one rigid part move together and count as one object: one camera may see one tag of a part and the other camera another, and both still meet in one pose. The wrist part turns only about S4 relative to the forearm, the gripper only about S5 relative to the wrist, so few views constrain the fit. Each tag seen by two cameras is also triangulated on its own. Tracked minus commanded angle is what the HOME calibration still gets wrong.

    Robot API and backend

    Use it from your own code

    GET  /api/state
POST /api/move      {"channel": 0, "target": 400}
POST /api/go_pose   {"name": "HOME"}
POST /api/stop      {}
GET  /api/backend           which arm answers
POST /api/backend   {"target": "sim" | "real"}

    POSTs need Content-Type: application/json and Origin set to this server, like the real controller. With the real arm active, every motion call is simulated first and answered with HTTP 409 if it would collide.
